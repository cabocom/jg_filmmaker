## 2. Puntos Débiles y Riesgos Operativos a Vigilar en Producción

A pesar de que el código base y la arquitectura son robustos, la operación en un entorno real con tráfico concurrente presenta áreas de fricción y riesgos operacionales que deben ser gestionados:

```text
+---------------------------------------------------------------------------------------------------------------+
| TOPOLOGÍA DEL SISTEMA Y PUNTOS DE ATENCIÓN OPERATIVA                                                         |
+---------------------------------------------------------------------------------------------------------------+
|                                                                                                               |
|    [ Navegador Cliente ]                                                                                      |
|             │                                                                                                 |
|    HTTP / Livewire (Polling wire:poll cada 3-5s)  <-- [PUNTO DÉBIL 3: Saturación HTTP por sondeo]             |
|             ▼                                                                                                 |
|     ┌──────────────┐     Disparo Jobs      ┌───────────────────────┐                                          |
|     │ Nginx / FPM  │ ────────────────────> │ Worker de Cola        │                                          |
|     └──────────────┘                       │ (php artisan queue)   │                                          |
|             │                              └───────────────────────┘                                          |
|      Lectura Vídeos                                    │                                                      |
|             │                              Normalización FFmpeg 1080p CFR                                     |
|             ▼                                          │                                                      |
|     ┌──────────────┐                                   ▼                                                      |
|     │ MediaStorage │                       [ Consumo intensivo de CPU ]                                       |
|     │ (Local / S3) │                       <-- [PUNTO DÉBIL 2: Cuello de botella en vídeos 4K]                |
|     └──────────────┘                                                                                          |
|                                                                                                               |
|  * [PUNTO DÉBIL 1]: Dependencia crítica del worker (si Supervisord cae, el procesamiento se congela).         |
|  * [PUNTO DÉBIL 4]: Ausencia de cuota dura de disco en gigabytes por usuario.                                 |
|  * [PUNTO DÉBIL 5]: Persistencia crítica de APP_KEY para la desencriptación de claves BYOK.                 |
+---------------------------------------------------------------------------------------------------------------+
```

### 2.1. Dependencia Crítica del Proceso de Colas (`queue-worker`)
- **Descripción:** Las tareas pesadas (transcodificación Mezzanine en `NormalizeTakeMediaJob`, renderizado de montaje en `AssembleRoughCutJob` y síntesis en `PrewarmScopeTtsJob`) dependen exclusivamente de la cola de Laravel.
- **Riesgo:** Si el worker de colas (gestionado por Supervisord o Docker) se detiene, la plataforma continúa aceptando archivos y peticiones de montaje, pero estos quedarán en estado `PENDING` indefinidamente sin que la interfaz informe de un fallo al usuario.
- **Mitigación Operativa:** Monitorización activa del proceso en Supervisord con reinicio automático y alertas de cola acumulada (`php artisan queue:monitor`).

### 2.2. Picos de CPU por Subida Concurrente de Vídeos en Alta Resolución (4K / Smartphones)
- **Descripción:** La estandarización Mezzanine convierte clips heterogéneos (H.265/HEVC, VFR a 60 fps) a H.264 1080p CFR a 24 fps con escala y letterboxing.
- **Riesgo:** Aunque se ejecuta en segundo plano, si múltiples usuarios suben simultáneamente vídeos pesados de rodaje, el consumo de CPU en el servidor host puede alcanzar el 100%, afectando la latencia de las peticiones HTTP del servidor web.
- **Mitigación Operativa:** Configurar el worker de la cola multimedia con concurrencia máxima limitada (`--max-jobs` o 1-2 procesos concurrentes dedicados exclusivamente a la cola `media`).

### 2.3. Sobrecarga de Peticiones por Polling en Livewire (`wire:poll`)
- **Descripción:** La mesa de montaje y el reproductor de guion consultan el estado de transcodificación y síntesis de audio mediante sondeo periódico HTTP cada 3 a 5 segundos.
- **Riesgo:** Con decenas o cientos de usuarios simultáneos en la sala de montaje, el volumen de peticiones HTTP a PHP-FPM crece de forma innecesaria, generando overhead de red y consumo de conexiones a base de datos.
- **Mitigación Operativa:** Migración planificada hacia WebSockets en tiempo real.

### 2.4. Ausencia de Cuotas Duras de Almacenamiento en Disco (GB por Usuario)
- **Descripción:** La plataforma dispone de control diario de tokens de IA (`daily_token_limit`) y límites de slots de proyectos, pero no cuenta con un límite duro de gigabytes almacenados por usuario en el sistema de archivos o bucket S3.
- **Riesgo:** Un usuario podría saturar el almacenamiento subiendo decenas de tomas en vídeo sin compresión.
- **Mitigación Operativa:** Implementar una validación de cuota de disco antes de aceptar subidas de archivos en Livewire.

### 2.5. Persistencia Crítica de la Clave Criptográfica (`APP_KEY`)
- **Descripción:** La bóveda BYOK utiliza el cifrado simétrico autenticado de Laravel Crypt para proteger las claves de API de los usuarios en la base de datos.
- **Riesgo:** Si durante un despliegue o reinicio de entorno se regenera accidentalmente la variable `APP_KEY`, todas las claves BYOK almacenadas quedarán corrompidas e imposibles de desencriptar.
- **Mitigación Operativa:** Fijar de forma inmutable la `APP_KEY` en los secretos del entorno de producción y respaldarla en la gestión de configuración segura.

## 3. Líneas de Futuro y Evolución de la Plataforma

Para evolucionar `jg_filmmaker` hacia una suite integral de referencia para la industria audiovisual y productoras independientes, se establecen las siguientes fases de desarrollo:

### Fase 1: Optimización de Infraestructura y Comunicación en Tiempo Real (Corto Plazo)
1. **WebSockets con Laravel Reverb:**
   - Sustituir el polling pasivo (`wire:poll`) en la línea de tiempo y en la síntesis de audio por eventos broadcast en tiempo real (`TakeNormalized`, `RoughCutAssembled`, `AudioSynthesized`).
   - Reducción del 90% del tráfico HTTP pasivo en el backend.
2. **Cuotas de Almacenamiento por Plan y Ciclo de Vida S3 (Lifecycle Policies):**
   - Incorporar columna `storage_limit_bytes` en `users` y computar el peso acumulado de tomas y renders.
   - Políticas de almacenamiento jerárquico: tras generar el proxy Mezzanine ligero (1080p), archivar automáticamente el archivo original pesado en almacenamiento frío (*Cold Storage / S3 Glacier / Cloudflare R2 Infrequent Access*).

### Fase 2: Colaboración Multiusuario y Flujos de Equipo (Medio Plazo)
3. **Salas de Montaje Compartidas y Control de Acceso por Roles (RBAC de Proyecto):**
   - Permitir a los autores invitar a colaboradores a sus proyectos con roles cinematográficos definidos:
     - **Director:** Control total sobre guion, storyboards, selección de tomas buenas (*circle takes*) y render de montaje.
     - **Guionista:** Edición de bloques narrativos, escaletas y diálogos en el editor Fountain.
     - **Script / Continuista:** Registro de tomas de rodaje, anotaciones técnicas y control de claqueta.
     - **Montador:** Ajuste de códigos de tiempo, puntos IN/OUT y exportación de líneas de tiempo.
4. **Bloqueo Concurrente Optimista por Bloque Narrativo:**
   - Prevenir colisiones de escritura cuando dos guionistas trabajan en la misma escena mediante locks efímeros en Redis.

### Fase 3: Interoperabilidad Universal y Despliegue Distribuido (Largo Plazo)
5. **Exportador Estándar OpenTimelineIO (OTIO):**
   - Extender el servicio `NleTimelineExportService` para generar artefactos `.otio` conforme a la especificación de la Academy Software Foundation.
   - Interoperabilidad directa y sin pérdida de metadatos con Adobe Premiere Pro, Avid Media Composer, Blender VSE y Nuke Studio.
6. **Worker Serverless para FFmpeg (Cloud Run / AWS Lambda):**
   - Desacoplar la transcodificación y el renderizado hacia contenedores serverless bajo demanda.
   - Permite escalar de 0 a 100 transcodificaciones simultáneas de vídeos 4K sin saturar los recursos de CPU/RAM del servidor web de la aplicación.
7. **Generación Multimodal Directa de Animáticas (Vídeo AI / Motion Storyboards):**
   - Evolucionar las viñetas fijas de storyboard generadas por `jg_plugin_filmmaker` hacia previsualizaciones animadas breves (animáticas con interpolación de movimiento o modelos generativos de vídeo), sincronizadas con las voces de los personajes sintetizadas por Google AI TTS.
